\section{Introduction}

{\color{pink} \it
The SPAP shall contain a description of the purpose, objective, content
and the reason prompting its preparation.

It is a constituent of the design justification file (DJF). Its purpose is
to describe the approach and the organization aspects and
management approach to implement the software verification,
validation and integration activities, tasks and processes.

Based upon the list of verification, validation and integration tasks,
the plan addresses the following items:
• the required tasks for each life cycle activity, software
• the procedure for forwarding verification reports to the
customer and other involved organizations.

Moreover, the document describes the testing, analysis, inspection
and review of design specifications, and is used to document:
• the software validation specification with respect to the
technical specification (TS), and
• the software validation specification with respect to the
requirements baseline (RB).

}

The purpose of the software product assurance plan is to provide information on the organizational aspects and the technical approach to the execution of the software product assurance programme. It is applicable for the ROSE-L Level-2 ocean processor software, i.e., L2O-GPP, L2O-IPF, L2O-COREALG, L2O-IO and L2O-VAM.

This document is following the ECSS-Q-ST-80C standard [ECSS-Q] with tailoring for the Copernicus Expansion Missions [ECSS-T]. The ECSS-Q-HB-80-04 software metrication handbook [ECSS-H] was used as a guideline.
